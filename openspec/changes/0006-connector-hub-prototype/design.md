# Design

Keep provider definitions in gemini-product.ts, enrich them with structured demo capability metadata, and put property normalization, mapping, serialization and destination readiness in shared typed libraries. Configuration, demo eligibility, real contractual authorization and remote connectivity are separate facts. Bayut/Dubizzle remains eligibility-blocked pending geography/partner confirmation; local setup cannot waive it. Other local examples remain explicitly unverified remotely.

Normalize saved facts into a scalar export model with bilingual text, numeric values, coordinates and available sample media count. Version internal destination maps, validate mapped required values plus canonical example policy, serialize XML/JSON/CSV with escaping, XML character handling, finite numeric checks and CSV formula neutralization. No provider schemas or tokens are invented. Preview/download reads current canonical revision; links preserve property/destination context.

Retain schemaVersion 1 for compatibility and add an additive connectorSchemaVersion 2. Migrate old jobs into mapping/attempt snapshots; validate every added field at hydration and discard malformed records with visible recovery. Keep queued-demo/blocked-demo compatibility, add cancelled-demo; derive revision-changed state from current property revision. Retry appends an attempt to the same local job after current approval/revision/plan/setup/mapping checks. Cancellation releases reservation and appends audit metadata. Failed retries preserve errors. Command functions are the authority for quotas and approval, including current context tokens; buttons only expose those commands.

Task-native directory rows, section links for provider requirements/mappings/feed/activity/diagnostics, canonical feed inspector, compact job filters with inline contextual inspector. Use existing px/gm tokens, semantic tables, keyboard controls, logical CSS and translated primary Arabic actions while disclosing incomplete professional localization.
