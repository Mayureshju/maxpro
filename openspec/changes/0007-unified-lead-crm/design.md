# Design

The existing maxpro-gemini-v3-demo-state repository owns properties, jobs and additive crmSchemaVersion 1 CRM data. No second storage key or competing lead source. Migrate pre-CRM envelopes into privacy-safe built-in examples linked only to existing current-organization properties. Validate hydrated entities, foreign keys, enum values, timestamps, references and routing cursor; exclude invalid CRM records with visible recovery while preserving valid properties/jobs. Unknown properties and lead IDs produce errors, never sample fallback.

Canonical lead owns organization/property IDs, immutable first-touch source/event/time and typed attribution history and optional destination/campaign reference, demo identity, consent/preferences, stage/priority/qualification, assignment decisions, embedded conversation/messages, notes, viewings and activity. Embedded records are referenced by their IDs and inherit tenant/lead/property ownership. Fictional contact identities only: generated Demo visitor alias and example.test address; raw arbitrary payloads are never stored. All provider contracts are internal illustrative examples.

Normalize website enquiry, Property Finder, Qatar Living, Meta Lead Ads and WhatsApp examples through shared library mappings. Dedupe key is JSON tuple organization/source/original event ID, never name. Record append-only received plus accepted/rejected/duplicate receipts with safe metadata. Duplicate replay does not advance routing cursor or mutate lead. Reject malformed input, future/invalid times, foreign organization, unknown property, incompatible destination and non-demo identity. Keep source time separate from received time.

Persist round-robin next-agent cursor as monotonic accepted rotation count. Eligible means known organization agent, active and available. Manual leaves leads unassigned for human selection; fallback handles no eligible round-robin agent if known and available, otherwise backlog. Validate every reassignment. Decisions include reason/time/previous owner; no reload routing side effects. Local single-browser commands provide no durable or concurrent routing guarantee.

Stages New/Contacted/Qualified/Viewing/Won/Lost; qualification is separately recorded. A Qualified transition sets qualification; closure retains it. Conversation messages carry channel, inbound/outbound, timestamp and local-only status. Consent opt-out blocks local replies. Handover uses the same assignment command. Viewing owns local date/time, lead property and known agent, Requested/Confirmed/Completed/Cancelled transitions; warn and prevent local overlapping agent/property requests within an hour, and disclose example weekday availability, never live calendar checks.

Reporting filters lead received dates inclusively using Qatar +03 dates, immutable first-touch source and optional property. Count total/new/qualified/won/backlog, won/total conversion, valid nonnegative first-outbound response time and property performance. Explicit dated fictional spend rows alone support CPQL in the same channel/date window. Missing cost/views/revenue are unavailable; publishing jobs never create traffic/cost/revenue. Control tower reads same leads.

Preserve px/gm tokens, editorial table and horizontally scrollable six-stage pipeline, detail dossier and split-pane inbox, routing policy and decision ledger, booking agenda, source report. Use semantic labels, status/alert feedback, focus-visible, logical CSS, EN/AR primary controls and real RTL. Loading, empty, invalid-ID, recovery, demo-permission acknowledgement, validation and success states are explicit. Arabic requires professional completion.
