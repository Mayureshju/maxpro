# Lifecycle acceptance

## GEM-02 — one property record
- Create assigns unique stable ID and fictional organization; blank/incomplete drafts save and survive reload.
- Inventory search/status filters and detail render canonical updates; revisions increment and event history persists. Unknown IDs on every property route and Studio/publish query never substitute samples.
- Valid Phase 0 edits migrate; malformed envelopes, fields, numbers, media and jobs cannot crash routes or fabricate readiness. Storage failure is visible and permits in-memory use.

## GEM-03 / GEM-21 — source and content review
- Studio starts blank or opens the selected record; user-supplied notes remain supplied notes. No arbitrary source produces invented extraction. Document/voice selection explicitly requires manual fact entry.
- Fictional sample is opt-in. Proposed EN/AR copy stays separate from canonical approved facts. Explicit review saves into the same ID, records source/review metadata, and gates handoff. Fact edits invalidate review; media/copy metadata persists with that record.
- English and Arabic routes retain locale, Arabic direction and primary translated actions. Keyboard can create/save/navigate/reorder/approve.

## GEM-04 / GEM-05 — actual media and validation
- Room category, order, removal and availability persist. No binary/data/blob URL enters storage; a newly selected file is metadata-only and never claims an uploaded asset. Bundled example availability is explicit simulation.
- Preflight reads current title/copy/price/specs/location/permit/owner review and categorized available media. Remove/reclassify/mark unavailable changes validation; floor-plan rule differs by destination. No hardcoded count lookup drives checks.

## GEM-08 / GEM-18 — local destination jobs
- New properties appear in publish picker and context links select the correct ID. Prepared connectors, approval and current revision checks govern simulation.
- Starter/Pro restrict 3/25 distinct queued listings and 1/2 portal reservations respectively; drafts may exceed quotas but cannot queue beyond them. Agency limits remain negotiated illustration. Starter excludes Meta catalogue. UI and command guards both enforce restrictions.
- Each selected destination records queued-local or blocked-local and reasons against the submitted revision. References and jobs survive reload and remain inspectable from property and global history. No local event yields external ID, remote success or accepted state.

## Verification / non-UI
- Install locked dependencies, execute root typecheck/lint/build and full existing plus new Playwright tests. Preserve existing functionality and regressions; report actual counts and prerequisites.
- Real app screenshots cover the new journey in EN/AR at desktop/tablet/mobile. Inspect captures, repair observed overflow and preserve editorial operational styling.
- No production backend/provider/AI/payment calls, sensitive demo persistence, commit, push or deployment.
