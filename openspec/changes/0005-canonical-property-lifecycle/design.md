# Design

`CanonicalProperty` contains ID, organization ID, revision, status, structured draft facts (bilingual copy, purpose/payment, specs, amenities, location and compliance), ordered media, supplied source/proposed content and factual review state, revision events and destination references. Records map to the property/translation/media/revision/publication boundaries in docs/12; the browser repository is a replaceable prototype adapter, not tenant authorization.

The provider owns the sole operational repository with a versioned envelope and runtime validation. Hydration distinguishes loading/missing/corrupt/unavailable storage. Legacy draft overrides migrate into seed records once; unknown IDs never fall back to another record. Preserve only known fields and bounded metadata. Store no binaries, blob URLs, credentials or customer contact data. Uploaded files have session previews; persisted metadata is explicitly unavailable for delivery. Re-selection is required after reload. Fictional bundled samples can be explicitly added for local simulation and are labelled as such.

Create blank incomplete drafts with cryptographic unique demo IDs. Save/review/media changes increment revisions and append event metadata. Editing facts invalidates factual approval; Studio keeps supplied notes and proposed copy separate until explicit human approval saves into canonical facts. Arbitrary notes/documents/voice never generate canned extracted facts; a labelled sample loads only fictional fixtures. Draft saves do not imply approval. Studio resumes from canonical source/proposal state.

Inventory is a searchable/filterable semantic table with optional gallery; detail/editor/media/Studio/publishing use the same records. Dynamic browser IDs resolve after hydration, not from server fixture allowlists. Context links preserve the chosen property. Unknown IDs get an explicit recovery view.

Preflight validates current facts, review state and available categorized media, including a separate floor-plan example rule. Dispatch rechecks current record/revision, plan, destination count, existing reserved listing/destination usage and connector readiness at command time. Incomplete drafts remain saveable. Listing quotas count distinct locally queued properties (not incomplete drafts); portal limits count unique portal destinations across local reservations plus selection; Meta has its separate illustrative Starter exclusion. Blocked attempts reserve no quota. Every attempt snapshots property revision and missing reasons, with no external reference or remote acceptance. Repeated dispatch is disabled until a new review cycle; each explicit later attempt remains history.

Use existing px/gm tokens, sectioned editor/inspector, ordered gallery and destination validation. Add Arabic copy for touched primary actions and guidance; partial legacy Arabic remains disclosed. Verify keyboard, EN/AR, 1440/1024/768/375px and actual browser screenshots. No additional framework.
