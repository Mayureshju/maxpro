# Acceptance

## GEM-10 / GEM-11
- Create from any current-organization canonical property; save/reload/edit/duplicate/cancel/resume keep identities and activities. Invalid IDs never substitute another campaign. Media references resolve to the same property.
- Ordered states: draft → pending-policy → policy-reviewed → pending-advertiser → pending-admin (if configured) → approved-local → simulated; cancel/reject are terminal until resumed as a new revision. Unauthorized roles, wrong tenant, stale revision, wrong order, over-budget and unsupported targeting reject at command level.
- Property/content/media/budget/targeting/configuration changes invalidate approvals. Revalidation includes current plan and local provider configuration. No remote launch, spend or acceptance is claimed.
- Catalogue is an internal example mapping of canonical properties with missing fields and eligibility limits; Google objectives/conversion goals/assets/budget link to campaign drafts. All account/region/feed/PMax permissions are unverified.

## GEM-21
- Deterministic bilingual suggestions, headline alternatives, feature references, objective, creative and explicit budget scenarios use only reviewed canonical facts. Missing factual review blocks suggestion creation. Accept/reject/edit records human history. No canonical fact is invented or overwritten. Weekly summaries require actual fictional campaign-linked observations and disclose the period/source.

## GEM-12 / GEM-24
- Fictional campaign lead goes through existing intake and organization/source/event deduplication. Repeat same event yields the same lead without advancing routing or mutating first touch. Lead detail exposes campaign reference.
- Reports reuse CRM selectors for linked/qualified/won/conversion, source/property filters; only explicitly recorded dated fictional campaign spend supports CPQL. Budgets, fees and approved budget are separate from spend. No reach, impressions, clicks, ROAS or actual spend.
- Consent-disabled event preview yields no payload; enabled preview uses the same local event ID for proposed client/server signals and never sends it.

## Storage / UI / evidence
- Older valid repository migrates without loss; malformed/oversized/foreign/stale records recover visibly while retaining valid unrelated entities. No credentials, binary creative or real contact data stored.
- Keyboard, EN/AR RTL and widths 1440/1024/768/375; save/errors/dirty/review-required/empty/loading/corrupt states. Axe checks for changed interactive content; real browser screenshots of portfolio/editor/creative/policy/approval/analytics in both locales.
- Preserve all Phase 1–3 tests; report exact install/typecheck/lint/build/full Playwright results, screenshot manifest and second-tool review status. No commit/push/deployment.
