## GEM-01/02/03/04/21/22: creation and guidance

A new agency starts empty and receives inline steps: create, complete information, review, choose a channel, inspect results. Each state uses saved records for one property. Incomplete/changed facts regress the corresponding readiness; clicking links never completes tasks. Dismissal survives reload only for that organization. Help reopens on demand; seeded/completed agencies keep their daily dashboard. UI must cover loading, empty, partial, complete, dismissed, validation and stale revision states.

Quick Add creates one fictional canonical draft through guarded commands. Full editor remains available. Incomplete drafts persist; step changes save and reload resumes the URL step. Direct review bypasses optional assistance. Invalid values identify the field; stale revisions cannot overwrite another view. English/Arabic labels, semantic controls, RTL, keyboard and mobile dock remain usable.

## GEM-05/06/07/08/13/14/16/24: connected outcome

Missing fields have a repair route; approval remains revision/context bound. Jobs remain blocked/queued/cancelled/revision-changed locally, with no provider acknowledgement.

A current local portal queue exposes an explicit fictional example enquiry action. Intake uses existing normalization/deduplication and assignment. Replay/reload returns the same source/property-linked lead, without duplicate leads, analytics counts or assignment rotation. Follow-up uses the existing CRM composer and commands. Where the fresh agency has no available owner/agent, a visible example-only action explicitly enables owner availability and assigns the enquiry using guarded commands; it never changes routing defaults. Switching organizations exposes none of the other organization's properties, jobs, examples or onboarding preferences.
